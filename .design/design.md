舟舟与小羊：专属 520 网站设计与后续规划

这份文档记录了构建“清新极光版”二人世界网站的核心提示词（Prompt），详细规划了四大专属生活模块的功能细节，并针对未来演进为“微信小程序”和“安卓 APP”提供了全栈架构升级指南，特别是创新的“前台沉浸式内容管理”方案。

阶段一：现有页面的设计提示词（Prompt）库

如果你需要在其他 AI 工具中复现、修改或拓展当前首屏的风格，可以直接使用以下结构化的提示词：

1. 全局视觉与背景设定

Prompt:
“请帮我使用 Tailwind CSS 设定一个网页的全局样式。要求摒弃传统的沉重深色模式，改用**『清新极光风』**。

背景使用动态的线性渐变（linear-gradient），颜色交织薄荷绿（#d1fae5）、淡紫（#f3e8ff）和浅蓝（#e0f2fe），并带有缓慢的呼吸动画（15s 周期）。

字体采用高级的混合排版：中文使用 Noto Serif SC（思源宋体），英文字母和数字使用电影感的罗马衬线体 Cinzel 和细体 Montserrat。

强调色定义为：高级薄荷绿（#10B981）和浪漫紫（#8B5CF6）。”

2. 高定毛玻璃胶囊导航栏

Prompt:
“请实现一个固定在页面顶部的『胶囊型导航栏』。

风格采用通透的亮色毛玻璃质感（Glassmorphism），背景为 rgba(255,255,255,0.4)，带有 16px 的高斯模糊和极细的白色边框。

导航包含四个普通链接（颜色为灰蓝，Hover 时变为薄荷绿），以及最右侧一个带有白色背景和右箭头的『高亮按钮』，具有点击缩放反馈（active:scale-95）。”

3. 防抖动电影感倒计时

Prompt:
“请使用 HTML/JS 写一个正计时/倒计时器，要求绝对不能出现数字跳动、宽度闪烁的问题。

核心方案：为包含数字的 div 设置强制的固定宽度（如 w-20 md:w-32），并在 CSS 中启用 font-variant-numeric: tabular-nums。

视觉上，数字要超大（text-8xl）、极细（font-light），底部的文字标签具有超大字间距（tracking-[0.5em]），整体浮于带有深色渐变遮罩的背景图之上。”

阶段二：专属生活模块功能规划

随着 520 的到来，首页将作为入口，后续通过导航栏接入以下四个深度定制的互动模块：

🍕 模块一：小餐馆 (Our Restaurant)

核心定位：两人专属的“人间烟火气”档案库。

功能 1：美食探店日记：记录一起去外面吃过的美食。采用瀑布流布局展示菜品照片，并附带时间、地点以及两人的专属打分和真实评价。

功能 2：专属私房菜谱：记录小羊为舟舟做过的饭，或者是两人一起研发的菜谱。包含食材清单、步骤和“翻车/成功”小贴士，方便随时复刻。

🍷 模块二：小酒馆 (Our Tavern)

核心定位：微醺时刻与夜间谈心角。

功能 1：微醺图鉴：记录两人在外面喝到的惊艳酒款、探店过的优质酒吧。

功能 2：调酒笔记库：一个类似“字典”的查询系统。记录你们喜欢的特调配方（如基酒比例、配料等），带有搜索和分类功能，方便你们在家里自己动手调酒时随时查阅。

💊 模块三：小诊所 (Our Clinic)

核心定位：最贴心、最实用的健康守护站（此模块极具现实意义，是核心功能点）。

功能 1：生理期跟踪仪：记录和预测舟舟的生理周期，特殊日子到来前可以触发页面的“暖心提示”。

功能 2：女性好物备备忘录：记录舟舟习惯使用/不会过敏的卫生巾品牌、尺寸及购买渠道，避免买错。

功能 3：健康预防小贴士：专门整理的妇科疾病预防注意事项、日常保养指南，作为一个随时可查的健康小百科。

功能 4：用药记录与提醒：设置用药日历。舟舟生病时，可以设置定时吃药提醒，并记录每天的服药情况。

🏛️ 模块四：纪念博物馆 (Memorial Museum)

核心定位：动态生长的爱情编年史。

核心功能：时光轴 (Timeline) 展览。一条纵向贯穿页面的发光时间轴，将你们的“第一次”串联起来：

第一次告白、第一次牵手。

互相送给对方的有意义的礼物（附照片和背后的故事）。

第一次一起看演唱会的票根记录。

第一次共同旅行的足迹地图。

阶段三：全栈架构规划与多端演进（小程序/APP）

为了解决“内容维护繁琐”的问题，同时避免“传统后台管理系统太重、体验割裂”的痛点，我们采用“前台直编（In-App Editing）” + Uni-app 的现代化架构。

1. 数据维护革命：摒弃传统后台，采用“隐藏式前台编辑模式”

不必为了发布一张照片特意去登录一个死板的后台网页，我们将“后台功能”直接融入前端日常页面中！

具体解法（情侣专属创作者模式）：

隐藏入口：在小程序/APP的前端页面，普通访客看只是一个展示页。但当你们“长按顶部 Logo 3 秒”或“快速点击底部红心 3 次”时，会弹出一个隐藏的密码框。

所见即所得：输入你们的专属暗号后，页面解锁进入“编辑模式”。此时，时光轴旁边会自动多出一个美观的 + 添加纪念日 按钮，食谱页会多出 + 上传新菜 按钮。

无缝上传：点击按钮，直接在当前页面弹出精美的对话框，选择手机相册里的照片、输入文字，点击保存，页面立刻刷新显示新内容。这种体验极度顺滑，完全不会打破浪漫的氛围。

2. 前端跨端框架选型 (Web -> 小程序 -> APP)

强烈建议直接使用 Uni-app + Vue 3 框架。

为什么选它？ 一套代码，同时打包成：微信小程序、安卓 APP (.apk) 和现在的 H5 网页版。

UI 无缝过渡：完美支持当前写好的 Tailwind CSS 极光风样式。

原生能力：打包成小程序或 APP 后，可以直接调用手机的相册、摄像头和地理定位（比如去哪家餐馆吃的美食，直接一键获取当前位置存入数据库）。

3. 数据与后端选型：Serverless (云开发)

有了“前台编辑模式”，你的前端代码需要直接把数据存到数据库里。

方案推荐：uniCloud 或 微信云开发

你不需要购买服务器。框架自带云数据库。

在你触发前台的 + 添加记录 按钮后，Vue 前端直接调用 uniCloud.database().collection('museum').add({ title: "第一次看海", image: "..." })，照片会自动上传到云存储，数据直接入库。

安全可靠：即使不写任何 Java/Node.js 后端代码，也能完美实现数据的永久保存。

🚀 总结你的开发者 Roadmap：

当前 (520 节点)：直接用生成的纯静态 HTML 文件，把首屏照片和倒计时写死，部署在 Github Pages 作为 520 惊喜首发。

架构重构期 (520之后)：下载 HBuilderX，把静态页面转为 Uni-app 项目，打通多页面路由（拆分出餐馆、诊所等页面）。

“暗号模式”开发：开通云数据库，在前端写好“暗号解锁”逻辑，开发美观的前端上传表单弹窗。

功能填充期：逐个开发生理期记录、调酒配方查询等功能。

最终形态交付：打包出微信小程序，你们俩可以在微信里随时随地发照片；打包出安卓 APP 装在手机里，作为终极纪念版。

阶段四：多媒体与 BGM 最佳实践 (开发防坑指南)

在为网站添加背景音乐（BGM）或音效时，有几个关键的技术细节和浏览器规范需要牢记：

1. 音频格式选择策略

网页并不强制要求使用 .mp3 格式，现代浏览器支持多种音频编码。推荐根据实际手头资源进行选择：

.mp3 (最推荐)：压缩率高，音质对网页播放而言绝对够用，并且具有几乎 100% 的浏览器兼容性，是最稳妥的 BGM 选择。

.m4a / .aac：苹果（Apple）主推的格式，同等文件体积下音质优于 MP3，目前绝大部分移动端和现代浏览器也都完美支持。

.ogg：开源、免费的音频格式，音质优秀。但缺点是在部分老旧的 iOS 设备或 Safari 浏览器上兼容性略差。

.wav (严重不推荐)：无损波形音频。虽然声音极其清晰，但未经压缩，导致文件体积非常巨大（一首歌可能高达几十 MB），会严重拖垮网页加载速度，导致体验卡顿。

最佳代码实践 (格式回退机制)：
建议在 <audio> 标签中提供两到三种格式，浏览器会自动挑选它能播放的第一种：

<audio id="bgm" loop>
    <source src="music/our-song.mp3" type="audio/mpeg">
    <source src="music/our-song.ogg" type="audio/ogg">
    <source src="music/our-song.m4a" type="audio/mp4">
    <!-- fallback 提示 -->
</audio>


2. 突破浏览器“自动播放”限制 (Autoplay Policy)

核心痛点：这是前端开发中极为常见的问题。现代浏览器（如 微信内置浏览器、Chrome、Safari 等）为了防止扰民，默认禁止网页在没有用户交互的情况下，自动播放带有声音的媒体。因此，直接在 <audio> 标签写上 autoplay 往往是无效的。

优雅的解法：
千万不要使用各种违背浏览器规范的黑科技去强行自动播放，而是应该在 UI 层面设计一个自然的“交互开关”。

视觉控制按钮：在页面角落设计一个精美的悬浮播放按钮（例如现在的胶囊毛玻璃唱片机图标）。

事件联动机制：当用户进入网页时保持静音，但在用户产生第一次有效点击时（如点击“开启告白”按钮、点击查看相册），通过 JavaScript 的 click 事件顺势调用 audio.play() 播放音乐。这样既符合浏览器规范，又能营造出“点击触发惊喜”的仪式感。

3. 进阶体验：专属悬浮歌单面板 (Interactive Playlist)

为了提升互动仪式感，建议将单一的播放/暂停按钮升级为“可自选歌曲的播放列表面板”。这样不仅能收录双方共同喜欢的音乐，也让网站更像一个专属的音乐播放器。

UI 交互设计：

点击右下角的唱片触发器（Trigger），向上弹出一个带有通透毛玻璃质感的列表面板。

面板需包含：歌单列表、当前播放歌曲状态栏，以及主控播放/暂停按钮。

数据与状态管理：

在 JS 中维护一个 songs 数组（包含 title 和音频 url）。

支持点击列表中的任意一首歌曲进行无缝切换。

正在播放的歌曲在列表中具有特殊的视觉高亮（例如加粗、变为强调色、并展示跳动的音轨图标）。

自动化控制：

监听 <audio> 标签的 ended 事件。当一首歌曲播放完毕时，自动计算 nextIndex = (currentIndex + 1) % songs.length，并执行播放，实现歌单的自动循环。
